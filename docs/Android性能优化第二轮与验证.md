# Android 性能优化第二轮与验证

日期：2026-10-16。用户要求完成代码审查提出的六项优化，并授权子 agent 并行实现。

## 实现

| 路径 | 优化 | 保留的行为 |
| --- | --- | --- |
| 矩阵 | 共用可见周期窗口，保留可能的部分尾列及左右各一列预取；窗口首尾同列推进，屏外列以精确像素占位 | 列宽、密度、颜色、表头对齐、完整滚动范围、单元格及价格/TV 警报入口 |
| Guaili 小组件 | 矩阵成功刷新只更新消费 legacy 快照的 Signals / Matrix / SingleSymbol ID | V2、决策提醒各自来源；快照订阅及更新时间 |
| TV 警报 | 相同刷新共享请求；编码和 RemoteViews 构建在后台；合并重绘 | 网络等待期间删除/重设仍可完成；旧列表不能回滚已确认修改；worker/广播等待发布 |
| V2 / 回调 | 单个后台工作器持有缓存，只保留最新排队输入；隐藏回调不计算候选 | 原刷新周期、到期边界、选择与滚动、未知不消失、静默提醒基线 |
| K 线 | 一次融合遍历共享 TR / EMA20 / ATR14 原生数组；直接创建最终图表行；滚动极值使用单调队列 | 初值、预热空值、分位数、历史修订及完整滑窗重算的逐点数值 |
| 启动 | IO 恢复账户；匹配且时间有效的矩阵缓存先显示，网络独立刷新 | 配置/规则/账户隔离；旧缓存或旧计算不覆盖新结果；加载期间保持系统返回 |

后台结果发布同时校验输入版本和时钟边界。时钟检查等待最新投影完成，再使用它的下一边界，避免异步化后阶段切换晚一秒。时间从暂不可确认恢复有效时，即使快照与 boot 未变也重建回调。

矩阵窗口的首尾共同由首个可见周期计算，并预留同一列最后一个像素位置可能需要的部分尾列。固定视口下每跨一列最多改变一次窗口，避免非整列宽度时首尾分别变化引起两次重组；与原窗口相比最多额外保留一列，可见内容和两侧焦点缓冲不减少。

TV 快照观察值携带 scope 与 generation。编码、IO 流缓冲、组件构建以及同账户重新登录后均重新核验，避免跨账户或旧会话结果进入 UI。删除/重设沿用原请求 generation，排队切到 IO 后也不能修改新会话。组件发布顺序票据先登记再读取数据，旧批次不能抑制新批次。刷新、删除、重设的返回路径仅更新操作状态，警报内容统一由观察流发布，避免重绘等待期间的新修改被旧返回值覆盖；退出广播不重复清理 SessionStore 已原子清理的缓存。

缓存恢复在后台和发布时分别校验配置、规则、boot、请求时间与缓存年龄；网络先完成时缓存失效，配置 B 缓存已恢复后排队启动的 B 请求继续保留它。

## 测量方法与适用范围

旧 APK 已保存在 `build/performance/20261016-before/`。原有 `StartupBenchmark.matrixScroll` 在竖屏 Auto 布局下实际进入品种分组，不能用于证明矩阵虚拟化收益。新增 `MatrixViewportBenchmark` 显式切换 Table 模式，并验证首列在滑动后确实移动或离屏；同一测试器可运行保存的旧 APK 和本次新 APK。冷启动、原分组手势、K 线平移仍保留为回归基准。另新增 40 品种 × 28 周期完整快照的 V2 / 回调滚动基准，避免只用空信号评估后台投影。

K 线独立 JVM 微基准先逐点比较输出，再各预热 5,000 次，进行 7 轮交替测量，每轮各 2,000 次；输入均为 300 根 K 线：

| 指标 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 计算时间中位数 | 80.68 μs | 35.80 μs | −55.6% |
| 单次线程分配 | 172,952 B | 100,336 B | −42.0% |

记录与对照脚本在 `build/performance/kline-parity/`。这只衡量本地 JVM 计算，不代表 Android 帧率。模拟器帧耗时也不能外推真机收益；真机验证使用 `scripts/measure-performance.ps1`，不加 `-AllowEmulator`。
