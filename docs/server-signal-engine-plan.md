# 后端动态乖离信号实现说明

更新：2026-10-02。后端功能已经实现，企业微信真实发送需填写自己的 Webhook 并重载配置。

后端位于 `F:\test\crypto-candlestick`。服务器按配置间隔采样当前动态 K，提供小组件查询接口，并按少量企业微信规则发送警报。最新实际契约见 [HTTP 接口文档](../../crypto-candlestick/docs/api.md) 和 [算法说明](../../crypto-candlestick/docs/guaili.md)。

## 配置与总开关

独立配置为 [signals.toml](../../crypto-candlestick/signals.toml)，模板为 [signals.example.toml](../../crypto-candlestick/signals.example.toml)。当前配置启用计算、间隔5秒，symbols=[]覆盖config.toml全部8品种；警报段均为注释示例。

`enabled` 是这套信号计算与关联企业微信警报的唯一总开关。关闭后，查询接口返回 disabled 和空结果。已在网络中接受的消息无法撤回；排队旧任务及发送中的后续重试会取消。行情采集仍运行。

每段 `[[wecom_alerts]]` 配置 id、名称、Webhook、品种、信号类型和最小发送级别。最小级别按候选结构的最大周期筛选，不改变计算输入。最低15分钟时，1–8分钟共振不发送，3–15分钟共振发送。分歧按长周期一端的最大级别判断。同一事件发往同一Webhook去重，默认冷却300秒；冷却内抑制的匹配不会延后补发。

修改文件后调用 `POST /api/signals/reload`。配置先完整校验，再原子替换；错误配置返回400并保留旧配置。计算配置改变重新建立信号基线，警报配置改变重建通知基线。运行配置可能包含凭据，已加入忽略规则；查询接口不回显Webhook。

## 动态计算

输入为最多499根连续历史已收盘K加1根当前动态K。当前K使用截至采样时的高、低、收、成交量，允许 isClosed=false，计划closeTime晚于现在正常。

继续使用后端既有 compute_guaili：整根K在均线上方，以low到MA的距离除以前一根ATR14；下方以MA到high的距离取负；跨均线为0。整数value为原始guaili乘10向零截断。atrLen用于rank过滤，乖离分母仍是前一根固定ATR14。

三类结构保留阈值：至少5个相邻周期同为value≥10或≤−10；至少5个周期绝对值≤2；正负两段各至少5个周期形成分歧。输出全部有效候选，并给小组件一个主信号引用。周期按真实时长排序；缺失、过滤及未知周期打断区间。

行情每次更新各周期动态K后，发布同品种完整快照。信号任务每5秒取快照，在锁外计算；不重叠执行，错过的调度点跳过。历史缓存按当前桶和恢复代际复用，未变化且仍有效的结果复用。查询只读缓存，没有额外指标计算。

两个采样点之间短暂出现又消失的结构可能漏掉。首次命中时间是采样观察时间，不能声称精确市场起点。收盘研究中的概率不能直接用于此动态采样算法。

## 数据质量与恢复

默认EMA20要求60根连续已收盘历史，当前动态K不计入预热数；计算窗口仍可达500根。新鲜度使用逐品种行情时间和接收时间，默认行情30秒、结果15秒。未知数据不构成信号解除，明确ATR rank超限则属于规则不满足。

Trade数据源支持逐成交动态快照；kline_1m支持当前未收盘分钟累计值更新的动态快照，先克隆已闭合前缀再加入最新分钟，不重复累计成交量。首连使用已收盘1分钟/日线前缀和精确成交ID补齐当前分钟，避免REST动态桶与排队成交重复累计。秒级启动/断流中的不完整桶不参与；其连续历史重新预热。内部基础周期不会通过公开接口暴露。

恢复代际改变后，计算中的旧快照不得发布，旧代际发送任务取消，首次有效恢复状态作为基线。查询在下一轮采样前也会隐藏已经失效的恢复代际结果。

## 查询接口

```http
GET /api/signals
GET /api/signals?symbols=BTCUSDT,XAUUSDT
POST /api/signals/reload
```

GET返回 enabled、status、计算间隔、configHash、runId、snapshotVersion、采样时间及 results。每个品种有 dataStatus、完整signals、primarySignal以及各周期证据。所有新接口时间均为Unix毫秒整数。

整体状态区分 disabled、warming_up、ready、degraded、config_error。无信号、关闭和数据不足有不同状态；过期缓存不显示为有效信号。查询的品种筛选不改变后台监控，也不受企业微信筛选规则影响。

小组件以后直接读取这份结果，按自身展示设置选择完整signals中的候选。重载接口没有新增身份认证，沿用现有部署访问边界。

## 内存与企业微信发送

配置、当前信号身份和通知去重均在文件或内存，不新增SQLite表。重启后不恢复历史事件，不补发停机期间信号；首次观测和恢复后的有效结构默认只建立基线。结构区间重叠时保持身份，扩大到订阅最小级别可产生首次符合提醒。不同不相交结构具有独立身份。

发送任务使用独立有界队列，不阻塞5秒采样。发送前核对配置版本、行情代际和时效；配置关闭、重载或断流会取消过时请求。每项最多重试3次，HTTP成功后还必须检查企业微信errcode=0。投递状态和最近错误只保存在有界内存。

## 源码与验证

主要实现：src/signals/config.rs、model.rs、detector.rs、delivery.rs、service.rs，查询入口src/http/signals.rs，行情一致性与恢复在src/memory.rs和src/binance/worker.rs。

验证涵盖动态K、同桶更新、预热、缺失/过期、完整历史合并、初始与恢复成交ID边界、配置重载、关闭时取消、查询无额外计算及企业微信本地模拟链路。未发送真实企业微信群消息，未修改业务数据库。

本机调试构建的模拟基准使用5品种、140周期、500根窗口：冷启动输入和计算约682毫秒，动态更新计算P95约47毫秒，未变化快照约0.44毫秒。这个结果来自隔离内存数据，不是实盘长期CPU测量。可运行 `cargo run --example signal_benchmark` 复现。
