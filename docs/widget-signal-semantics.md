# 小组件多周期结构与收线变化

规则版本：`closed-structure-v2`。本次实现继续使用最近已收线数据，不切换为动态 K 线。

## 来源核对

已核对相邻后端仓库的 [指标实现](../../crypto-candlestick/src/indicators/guaili.rs)、[算法说明](../../crypto-candlestick/docs/guaili.md)、[探索性验证记录](../../crypto-candlestick/docs/guaili-multi-interval-signal-validation.md)。后端无需更改接口。

- 整根 K 线在 MA 上方：`guaili=(low-MA)/previousATR14`；在下方：`(high-MA)/previousATR14`；触碰、跨越或分母为零时返回 0。
- 响应 `atr14` 是当前根 ATR14，不能拿它复算当前乖离。客户端现在至少请求 3 个点，供动态点、最近已收线点及其前一根 ATR 使用。已知分母无效时排除该点。
- `value=trunc(guaili*10)`，不是百分比。保留 `value>=10`、`value<=-10` 和 `abs(value)<=2`，最后一条实际包含原始乖离绝对值小于 0.3 的值，不偷偷改为精确 0.2。
- 趋势由均线连续三次同向变化及可选斜率条件产生，使用当前 ATR14 检查斜率；与乖离方向、rank 过滤独立。
- 原矩阵保留前一根趋势的显示习惯；新增信号趋势字段取同一根已收线点，避免错位。

## 三类结构

| 结构 | 条件 | 展示选择 |
| --- | --- | --- |
| 上方/下方乖离共振 | 相邻至少 5 个周期同号达到 ±10 | 各方向优先较长区间，再按最小绝对值、最大周期选择 |
| 多周期近均线 | 相邻至少 5 个周期整数绝对值 ≤2 | 较长区间优先；同长度优先较小的最大原始绝对乖离，再较小的平均绝对乖离，最后较大周期 |
| 长短周期分歧 | 正负两段各至少 5 个周期 | 优先总级别数，再最大周期；显示两段的方向、范围、各自级别数 |

相邻以配置中完整周期集合按时长排序为准；缺失、过滤、未收线、过期、未知时间及无效计算点打断区间。分歧开启时合并其正负共振；独立近均线结构仍展示。关闭分歧可查看两个方向的共振。数量是覆盖度，不是独立样本数或概率。

## 变化规则

比较前后成功保存的快照，并在同一事务快照中持久化结果。比较需要来源、周期、品种、MA/ATR/rank/斜率参数、计算窗口、收线模式和规则版本一致。展示偏好及刷新频率不改变配置身份。

每个参与周期的收线时间必须未变或恰好推进一个周期（允许 2 秒时间容差），至少一个周期推进才产生变化。同时间的历史点发生修正时重新建立基线。任何参与周期的证据缺失、过期或跨过多根收线时，都不能推断形成或解除。重复刷新保留上次状态，应用进程重启可以从磁盘快照继续比较。

| 变化 | 定义 |
| --- | --- |
| 首次观测 | 初次加载、旧缓存迁移、参数变化或证据中断后的基线；不能称为此时刚形成 |
| 新出现 | 连续有效观测从不满足进入满足 |
| 持续/持续近零 | 新收线后同一区间仍满足，未超过变化幅度门槛 |
| 覆盖区间变化 | 同一结构族的所选区间成员改变；不重复当作新形成 |
| 乖离收窄/扩大 | 同一区间平均绝对原始乖离减少/增加超过 0.1；不声称价格必然回调 |
| 分歧缓和/扩大 | 两段各自平均绝对乖离的均值减少/增加超过 0.1 |
| 短端向上/下离开近零区 | 原近均线区间最短两个周期均超过整数 ±2 且同方向；允许其余较长周期仍形成近均线结构 |
| 转为同向 | 原分歧两段的全部周期均超过近零区并变为同号 |
| 条件已不满足 | 数据可判断，但原规则退出；已知 rank 过滤失败也属于退出，不被解释为方向扩张 |

退出变化保留原区间并标记“变化”，不将历史区间称为当前有效结构；重复请求同一批 K 线保留，下一根相关 K 线推进后移除。所选候选区间更替不等于旧区间解除，须检查原参与周期是否真正退出。

趋势背景显示最大周期同根 MA 的方向。MA 上行且短端负乖离时附“回调结构观察”，下行且短端正乖离时附“反弹结构观察”；不将零乖离当作低波动，不把均线未满足斜率条件描述成已经横盘。

## 阈值与研究边界

来源研究支持保留现有 10/2/5 起始阈值，但它是特定历史样本、参数及采样口径的探索记录。8–60 分钟的样本结果不能推广到任意品种、大周期、秒级或新增变化规则；“未来盘中曾回撤”也不是实际收益。因而去掉“强风险”和预测方向箭头，不引入自动分品种阈值或命中率。

目前 API 不提供实际计算历史数量、预热完成与连续性元数据。返回 `count` 受响应 `limit` 截断，不能用它证明至少 60 根已收线历史；本版不伪造这个门槛。新规则仍统一标记“观察”。正式校准需取得可复现数据，固定品种/方向/参数/规则版本，以首次事件而非每次刷新计数，分时间训练与样本外验证，并报告期间顺向不利运动及交易时段影响。

本版变化是客户端轮询观察的已收线变化，不承诺完整捕获后台暂停期间的事件，也不等同于另行规划的服务端实时动态信号引擎。没有新增交易执行或外部通知。

## 2026-09-29 设备时间偏差修复

- 接口已有 `serverTime`，不改后端。快照新增服务器时间、接收响应时的 `elapsedRealtime`、本次启动计数和请求耗时。
- 行情判断时间为服务器响应时间加接收后经过的单调时长；缓存寿命也用单调时长。信号检测、变化比较、最新收线和主界面缓存判断统一接入。原客户端 `updatedAt` 保留供刷新操作反馈，获取时间显示使用服务器时间。
- 进程重启可以读回同次启动的基准；设备重启、缺少服务器时间、启动计数不可确认、请求耗时超过 5 秒时，提示时间暂不可确认并要求刷新，不把这些情况报成行情过期。5 秒是保守的请求不确定性门槛，不是数据过期门槛。
- 设备时间偏差超过 2 秒时显示“设备慢/快…… · 已按服务器时间判断”。真正晚于服务器时间的已收线点单列为收线时间异常；真正陈旧、过滤、缺失继续按各自规则处理。
- 新增测试覆盖慢 86 秒、快几分钟、日期偏差 ±16 天、运行中改日期、同启动进程恢复、重启、延迟过大、旧缓存迁移及真实陈旧/未来/缺失；刷新与持久化变化也验证服务器时间口径。最终 150 项单元测试通过，桌面测试 1 项通过，Debug 构建成功，Lint 0 错误、40 警告。
