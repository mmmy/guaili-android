# 小组件信号模式 v2

更新：2026-10-03。

原“信号模式”保留，现使用客户端获取的实时动态K计算；已保存的小组件配置和默认模式均不自动迁移。新增“信号模式 v2”从后端 `GET /api/signals?symbols=BTCUSDT,XAUUSDT` 获取当前动态K信号，计算配置在后端 `signals.toml`，使用独立缓存。

## 使用方式

在小组件的“编辑”页面选择“信号模式 v2”，选择最多10个品种及需要显示的三类信号，然后保存。服务器地址沿用应用的全局设置；本地 Android 模拟器使用 `http://10.0.2.2:3005/`。

v2从服务器返回的匹配结构中按原信号模式的规则选取展示项；点击卡片进入对应品种和最大周期K线。服务器的企业微信发送筛选不影响小组件查询。均线参数由服务器决定，手机不会再次计算这些信号。

每次查询合并所有已启用v2小组件的品种并去重，不把旧模式的小组件加入请求，也不将合集截断为10个，以便多个v2小组件共享缓存时都保留所需品种。如果某个手机所选品种未配置在服务器，接口返回HTTP400时回退到全量查询一次；已配置品种仍可显示，未配置品种在状态页提示“服务器未计算”。成功响应整体替换缓存，不拼接不同采样时刻的旧结果。

v2与原信号模式共用紧凑标题栏和信号卡片：第一行是品种、信号名称和级别徽标，第二行是周期范围、均线方向和状态。正乖离使用绿色，负乖离使用红色，近均线使用蓝色。均线名称来自接口的indicatorConfig；旧后端尚未提供参数时显示“均线?”。

后端默认每5秒采样。小组件在桌面上的后台刷新沿用系统周期任务，可能延迟；应用在前台刷新行情时也会刷新已启用的v2小组件。可以随时点击小组件的刷新按钮。服务器采样频率不等于桌面的更新频率。

## 状态与时间

服务器关闭计算时显示“服务器信号计算已关闭”。质量提示按实际原因区分“行情过期／部分过期”“连接恢复中”“历史预热／部分预热”“指标预热”“历史断档”“动态K缺失”“等待行情”和“数据异常”；手机缓存过期与服务器采样超时也分别说明。全部行情过期时显示“实时行情已过期，暂无法判断信号”，不把无法判断写成没有符合条件的信号。部分周期不可用时仍显示其他有效结构；点击状态标签查看各品种受影响的周期、具体分类，以及历史预热周期的实际连续历史根数。采样频率不代表行情每次都有更新。服务器不支持该接口时提示升级后端或使用原模式，不借用旧模式结果。

获取时间与服务器采样时间分别显示。手机使用服务器时间和单调时钟判断快照年龄，修改手机日期不会使旧信号重新变成有效。设备重启后要求重新刷新校准。缓存超过有效期后隐藏信号并提示刷新。

点击标题旁的状态文字可查看来源、采样/获取时间、时钟校准和各品种的数据可用性。

## 联调与数据保留

构建与单元验证：`:app:assembleDebug`、`:app:assembleDebugAndroidTest`、`:app:testDebugUnitTest`、`:app:lintDebug`。

模拟器验证使用 `ServerSignalsV2IntegrationTest`，覆盖真实接口解析、旧/v2模式配置与品种上限、全配置品种的动态K证据、品种子集查询和未配置品种回退，以及桌面显示和状态详情。测试要求已有小组件和已启动的本地后端，并在截图前确认桌面显示本次响应的获取时间。使用 `adb install -r` 和手动 instrumentation，不清除或卸载用户应用。

全品种验收默认检查本地配置的8个品种；配置变化时通过`expected_symbols=BTCUSDT,XAUUSDT,...`显式传入预期合集。该项要求计算开启，每次返回完整品种合集及真实行情序列与事件时间。测试最多观察90秒，要求每个品种期间至少出现一次可用的当前动态周期，不要求低成交量品种在同一瞬间全部新鲜，也不放宽服务器的新鲜度阈值。任一品种一直等待实时快照或整个观察窗口始终无可用动态周期均验收失败；历史不足或市场断流的周期仍如实显示可用性原因。

同一项验收还将同一次接口响应中可用的动态指标输入旧版实际结构检测器，比较v2展示的品种、信号类型、区间方向和周期、最大周期、级别数、均线趋势，以及各类信号开关组合。恢复中或过期的响应只检查状态正确且没有活跃信号，不计入有效品种观察；新鲜且可展示的响应才进行结构对照。对照使用相同的未收盘K、动态乖离和趋势值；生产原模式现使用动态K。首次观察、持续等状态和结构ID各自演进，不用于该一致性比较。规则参数应沿用原模式默认阈值10、近均线范围±2和至少5级。

设备配置已通过 `scripts/backup-widget-device.py` 备份。默认测试恢复原配置；显式传入 `keep_local_v2=true` 并且测试成功时，可以保留一个本地v2小组件用于查看。`expect_disabled=true` 用于后端开关关闭时的专门显示验证。

## 本地迁移验收记录（2026-10-03）

后端补齐分钟K来源的动态快照，原 `source=auto` 配置无需改成逐成交。实际8品种为BTC、XAU、CL、QQQ、CXMT、KORU、SOXL、UNITREE；验收期间每个品种都观察到可用的当前动态周期，不再仅有BTC/XAU能计算。秒级启动预热、上市时间较短的大周期不足60根历史，以及超过30秒未更新的行情，仍遵循 `signals.toml` 的质量门槛，不伪装为有效。

两个仓库使用相同的18场景JSON夹具，覆盖阈值、同方向多段、分歧、精确近均线排序及缺失周期屏障；Android遍历8种类型开关组合，对照原检测器。真实模拟器联调另以同一批接口动态指标验证结构、方向、区间、锚点、级别数、趋势和排序一致。两种模式均使用动态K；各自独立观测的首次/持续状态与ID不作为同批结构的一致性标准。

验证结果：后端 `cargo test` 171项通过；Android单元测试192项通过，构建和Lint通过；`ServerSignalsV2IntegrationTest` 5项真实联调通过。测试日志为 `build/signal-v2-acceptance-integration.txt`，模拟器截图为 `build/signal-v2-acceptance-widget.png`。本地服务与模拟器APK已更新，未部署远端服务器。
